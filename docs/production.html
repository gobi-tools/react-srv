... there's a number of things React Srv does inside the render method:

  1. First, it creates static markup (that includes initial props)
  2. Then, it creates a hydration script (for subsequent interactivity)

Therefore, at each request, the final payload consists of both HTML and Javascript:

The static markup is created at runtime from the component - <Page/> - itself.

The hydration script is also created at runtime by reading the file - Page.tsx - from disk.

In order to know where to find the file, React Srv needs to know where to look. By defualt it looks in the /src folder. This can be changed by specifying the srcPath parameter when initialising the shared object.

Prebundling

For small project or for developmement, reading from disk might be good enough. It does require the source always be present, however, and it does mean the same code will be compiled over and over again, at each request.

For production builds, it's always best to prebundle all the hydration scripts.

Select environment

One final step is to let React Srv know when you're running in a test environment and when in a production environment.

You can use the isProd config value to specify what environment to run in. The underlying logic is up to you.

When setup like this, React Srv will compile .tsx files on the go in test mode and server pre-compiled .js files from the bundle output folder in production model.

Caching

Every time your endpoint gets hit the client browser receives the generated HTML and Javascript. The size of the response depends on the amount of actual content in the source page, with smaller pages loading faster than bigger ones.

Apart from that, each page needs the React library loaded so hydration, interaction, re-rendering, etc can happen, just like in a traditional SPA. This would normally add quite a lot more Kb to each request.

Fortunately the library is loaded separately, meaning it's loaded only once, at the first request and then cached by the browser.

Similarly, the final bundled JS hydration code (in ./public/react-srv, for example) can be cached as well (you'll need to check your webserver's docs to see how that works).
